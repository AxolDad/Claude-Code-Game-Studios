# Bevy 0.20 Engine Support: Design

**Date:** 2026-11-02
**Status:** Approved (the owner asked for the complete implementation, push and merge on 2026-11-02)
**Branch:** `bevy-0.20-support`, based on `05ad7c8` (Release 1.2.0, identical to upstream `Donchitos/main` on this date)

## Goal

Add Bevy 0.20 to Claude Code Game Studios (CCGS) as a fourth supported engine.

`/setup-engine bevy` and the workflows after it must work on a real Bevy 0.20
project. Godot, Unity and Unreal must behave as they did before this change.

## Decisions

| Decision | Choice | Reason |
|---|---|---|
| Scope | Fourth engine beside Godot, Unity and Unreal | Nothing existing is removed |
| Approach | Add Bevy to each existing engine switch, table and doc | Follows the repo's pattern, leaves existing engine paths alone and stays easy to merge from upstream |
| Rejected: engine registry | Not built | Rewrites working engine paths with no CI to catch regressions, and per-engine logic such as output parsing is not data |
| Rejected: agents and docs only | Not built | `/test-setup`, `/smoke-check`, asset audits and content counts would report no Bevy support |
| Specialists | Five | Matches the other three engines |
| Reference version | `engine.version: 0.20.0` | The version requested |
| Scaffold dependency | `bevy = "0.20"` | Cargo resolves it to the latest 0.20.x, which is 0.20.1 on this date |
| Default engine | Stays Godot | The template's default import and examples do not change |
| Framework version | `framework.version` stays 1.2.0 | Changes go under an Unreleased heading in `CHANGELOG.md`, which keeps upstream merges simple |

## Verified facts

Every fact below was checked on 2026-11-02.

| Fact | Source |
|---|---|
| Bevy 0.20.0 was published 2026-10-08 and 0.20.1 on 2026-10-28, both with MSRV 1.97.1 | crates.io API |
| The local toolchain is cargo and rustc 1.98.0, which meets the MSRV | `cargo --version`, `rustc --version` |
| A test in `tests/unit/foo.rs` is not compiled, and `cargo test` still exits 0 | Throwaway Cargo project |
| A test in `tests/<name>/main.rs` is discovered and can import the library crate | Throwaway Cargo project |
| A filter matching no tests also exits 0 | Throwaway Cargo project |
| Custom naga_oil shaders must move to WESL and `.wesl`; plain WGSL keeps working | 0.19 to 0.20 migration guide |
| `ui::widgets::Button` and `ui::Interaction` are deprecated | 0.19 to 0.20 migration guide |
| `Query::iter_many` and related iterators now yield `Result` | 0.19 to 0.20 migration guide |
| `On<Add, A>` becomes `On<Add<A>>` | 0.19 to 0.20 migration guide |
| The `.bsn` asset format is listed under future work | 0.20 release notes |
| `bevy_ci_testing` is a Cargo feature, and `CiTestingEvent` includes `ScreenshotAndExit` | crates.io features, `v0.20.0` source |
| Linux needs `g++ pkg-config libx11-dev libasound2-dev libudev-dev libxkbcommon-x11-0`, plus `libwayland-dev libxkbcommon-dev` for Wayland | `docs/linux_dependencies.md` at `v0.20.0` |
| The recommended dev profile is `opt-level = 1`, with `opt-level = 3` for dependencies | Bevy setup guide, which still shows `bevy = "0.19"` |
| The repo has no CI workflows and no tests for its scripts | `.github/workflows` absent, `git ls-files` |

## Engine facts

| Fact | Bevy value |
|---|---|
| `engine.name` | `Bevy` |
| `engine.language` | Rust, with no language choice |
| Code root | `src/` |
| Crate layout | Required `src/lib.rs` holding game code, and a thin `src/main.rs`, so integration tests can import the game |
| Asset root | `assets/` |
| Test roots | `#[cfg(test)]` modules in `src/`, `tests/unit/main.rs`, `tests/integration/main.rs` |
| Test modules | Each system is declared with `mod <system>;` in its `main.rs` |
| `commands.smoke` | `cargo check` |
| `commands.test` | `cargo test --no-fail-fast` |
| `commands.build` | `cargo build --release` |
| Version source | `Cargo.toml` and `Cargo.lock`; there is no engine binary |
| Screenshot capture | `bevy_ci_testing` feature; reports `NOT VERIFIED` when no GPU or window is available |
| Scene guidance | `bsn!` macro and code-defined scenes; `.bsn` files are not treated as the scene format |
| Knowledge gap | HIGH, because 0.20 is newer than the model's training data |

### Hooks and scripts

| File | Change |
|---|---|
| `.claude/hooks/yaml-helper.sh` | Accept `Bevy` in `engine.name`, map the code root to `src`, map the primary specialist to `bevy-specialist` |
| `.claude/hooks/validate-commit.sh` | Add `.wesl` and `.wgsl` to the source file patterns, and correct comments that call `src/` Godot's |
| `.claude/hooks/validate-write.sh` | Trigger on `Cargo.toml` |
| `.claude/hooks/detect-gaps.sh`, `session-start.sh`, `validate-assets.sh` | Correct comments; check behavior against a Bevy fixture |
| `.claude/scripts/project-state.sh` | Map the code root to `src` |
| `.claude/scripts/write-guard.sh` | Add the code root, test roots and a rule that `/setup-engine` never replaces an existing `Cargo.toml` |
| `.claude/scripts/asset-scan.sh` | Add a `bevy` engine with root `assets`, excluding `.gitkeep` and Bevy `.meta` files; orphan and missing-asset checks report `not_run` with the reason |
| `.claude/scripts/content-count.sh` | Add a `bevy` engine with data extensions `json`, `ron` and `toml`; scene counts report `not_run`, because Bevy has no scene file format here |
| `.claude/scripts/test-scaffold.sh` | Generate `tests/unit/main.rs`, `tests/integration/main.rs`, a headless example test and a GitHub Actions workflow |
| `.claude/scripts/test-run.sh` | Add a `bevy` engine, described below |
| `.claude/scripts/project-coherence.sh` | Compare the major.minor of `engine.version` with the `bevy` entry in `Cargo.lock`, and report skipped when there is no lock file |
| `.claude/scripts/flaky-stats.sh` | Add a `cargo` format that reads `test <name> ... ok`, `FAILED` and `ignored` lines |

JSON validation stays as it is. RON and TOML files are not validated by the hooks,
and the Bevy docs say so.

### `test-run.sh` behavior

| Step | Behavior |
|---|---|
| Before running | Requires `Cargo.toml` and `cargo`; otherwise reports why and runs nothing |
| Build | `cargo test --no-run`, with its output in the separate pre-log, and no test run if it fails |
| Default test command | `cargo test --no-fail-fast` |
| Default timeout | 1800 seconds, matching Unreal, because a first Bevy build is slow |
| Count | Sums every `test result:` line |
| Zero tests | `zero_tests yes` and rule `bevy:zero-tests`, never a plain pass |
| Uncompiled tests | Reports any `.rs` file under `tests/unit/` or `tests/integration/` that no `mod` declaration reaches |

New rule IDs: `bevy:no-manifest`, `bevy:build-failed`, `bevy:0`, `bevy:zero-tests`,
`bevy:test-failed`, `bevy:other`. Like the rest of the script, these are
observations and not verdicts.

### Skills

- `/setup-engine`: add Bevy to the guided choice, version lookup, `CLAUDE.md` stack
  template, technical preferences, `project.yaml`, knowledge gap table, reference
  docs, scaffold and verification. Add `Bash(cargo --version)` and
  `Bash(rustc --version)` to `allowed-tools`.
- `/setup-engine` scaffold: writes `Cargo.toml`, `src/lib.rs`, `src/main.rs` and
  `assets/`. `Cargo.toml` sets `[profile.dev] opt-level = 1` and
  `[profile.dev.package."*"] opt-level = 3`, as Bevy's setup guide recommends.
  Version lookup uses crates.io, because that guide still shows `bevy = "0.19"`.
- `/test-setup`, `/smoke-check`, `/dev-story`: add Bevy steps for detection, test
  roots, CI, parse checks, test runs and screenshot capture.
- Other skills: `/gate-check`, `/architecture-decision`, `/architecture-review`,
  `/create-architecture`, `/security-audit`, `/prototype`, `/test-helpers`,
  `/test-flakiness`, `/soak-test`, `/asset-audit`, `/content-audit` and the rest
  of the list are reviewed under the rule above.
- Longer Bevy content goes into reference files that load only on Bevy, following
  `godot-language-config.md` and `engine-checks.md`, so other engines pay no extra
  context cost.

## New files

### Reference docs: `docs/engine-reference/bevy/`

- `VERSION.md`, `breaking-changes.md`, `deprecated-apis.md`,
  `current-best-practices.md`
- `PLUGINS.md`, covering third-party crates and how to check their 0.20 support
- `modules/`: `animation`, `audio`, `input`, `navigation`, `networking`, `physics`,
  `rendering`, `ui`, each within the repo's 150-line limit

Content comes from the 0.20 release notes, the 0.19 to 0.20 migration guide and
source tagged `v0.20.0`, and every file carries a "Last verified" date. Migration
entries are filtered to those that affect game code. A module must say so if Bevy
does not provide that feature itself. Any third-party crate named must have its
0.20 support checked and recorded with the date, or be marked unverified.

### Specialist agents: `.claude/agents/`

| Agent | Domain |
|---|---|
| `bevy-specialist` | Overall authority: architecture, plugins, Cargo features, performance and routing |
| `bevy-ecs-specialist` | Systems, schedules, observers, states, queries and Rust patterns |
| `bevy-render-specialist` | Materials, WESL and WGSL shaders, cameras and render features |
| `bevy-ui-specialist` | `bevy_ui`, Feathers, widgets, picking and input focus |
| `bevy-assets-specialist` | Asset loading and processing, glTF, BSN and data files |

Each agent follows the existing structure, including the Collaboration Protocol
and Version Awareness sections. Routing in `project.yaml` uses
`bevy-ecs-specialist` for the language slot, `bevy-render-specialist` for shaders
and `bevy-ui-specialist` for UI.

### Test specs: `studio-tests/agents/engine/bevy/`

One spec per agent in the existing format. `studio-tests/catalog.yaml` gains five
entries, and its agent totals become 54.

## Verification

1. **Real Bevy project, on this machine.** Use the new scaffold outside the repo:
   - `cargo check` and `cargo test` pass against Bevy 0.20, on the version Cargo
     resolves.
   - `test-run.sh` reports a non-zero test count on the scaffold.
   - A deliberately failing test gives `bevy:test-failed`.
   - A compile error gives `bevy:build-failed`.
   - Removing all tests gives `bevy:zero-tests`.
   - A test file no `mod` reaches is reported.
   - `flaky-stats.sh` counts real `cargo test` output.
   - Screenshot capture is tried once and its result reported as it happens.
2. **Other engines, before and after.** Run the changed scripts on minimal Godot,
   Unity and Unreal fixtures from `main` and from the branch, and compare the
   output. Every difference must be intended and explained.
3. **Bevy fixture through the hooks.** Run `yaml-helper.sh`, `validate-commit.sh`,
   `validate-assets.sh`, `session-start.sh`, `detect-gaps.sh`, `asset-scan.sh`,
   `content-count.sh`, `project-state.sh` and `project-coherence.sh`, and confirm
   each resolves Bevy and announces anything it skips.
4. **Repo checks.** `skill-lint.sh` and `agent-check.sh` report no new findings
   compared with `main`.
5. **End to end.** Run `/setup-engine bevy 0.20.0` in a clean copy of the template,
   then `/test-setup` and `/smoke-check`.

The work is finished when all five pass, or any exception is reported with its
actual output. The fixtures and comparison scripts are working files and are not
added to the template.

## Out of scope

- An engine registry or any restructuring of how engines are represented
- Changing the default engine or removing existing engines
- Building a game
- A CI workflow for this template repo; `/test-setup` still generates one for Bevy
  game projects
- Migrating projects from earlier Bevy versions, beyond what `/setup-engine upgrade`
  does for any engine
- Updating the stale knowledge cutoff in `docs/engine-reference/README.md`
- Pushing the branch or opening a PR without being asked

## Risks

| Risk | Mitigation |
|---|---|
| Reference docs are wrong because 0.20 is newer than the model's training data | Use primary sources only, and compile the key examples against the real project |
| A shared `src/` and `assets/` layout makes Bevy inherit Godot-only behavior | Review every `eng == godot` branch, and run the Bevy fixture |
| Editing shared scripts breaks another engine | Before and after comparison on fixtures |
| Upstream changes while this branch is open | Small additions in existing switches, new files where possible, and merge from upstream before any PR |
| Skill files grow past repo limits | Bevy-only reference files, checked with `skill-lint.sh` |
| Screenshot capture needs a GPU and a window | Report `NOT VERIFIED`, as other engines do when capture cannot run |
